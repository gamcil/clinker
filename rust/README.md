# Rust workspace

This directory is the in-progress Rust implementation of clinker. It is a
[Cargo workspace](https://doc.rust-lang.org/book/ch14-03-cargo-workspaces.html):
one repository containing several related Rust packages which share one lock
file, build directory, and dependency resolution.

## Packages

- `clinker-core` holds platform-independent parsing and analysis code. It takes
  GenBank bytes rather than paths, so it can later be used by both native and
  browser callers.
- `clinker-cli` is the small native command-line frontend. Its release binary
  is named `clinker-rs`.
- `clinker-wasm` will be added later as a thin `wasm-bindgen` frontend over the
  same `clinker-core` package. It now exposes browser-file analysis through a
  JavaScript-compatible function.

`Cargo.toml` is Rust's package manifest. It declares a package's name,
version, Rust edition, and dependencies. `Cargo.lock` is generated by Cargo
after resolving compatible dependency versions; commit it for applications so
local builds and release builds use the same dependency graph.

## Commands

Run all tests from this directory:

```bash
cargo test --workspace
```

Run the slower five-example compatibility baseline in release mode:

```bash
cargo test --release -p clinker-core --test golden_examples -- --ignored
```

It compares Rust's retained links against a baseline produced by clinker 0.0.32
with Biopython 1.80, at identity cutoffs of 0.30 and 0.70. It intentionally
does not assert exact traceback coordinates or all floating-point scores.

Run the early CLI against an existing fixture:

```bash
cargo run -p clinker-cli -- ../examples/'A. versicolor CBS 583.65.gbk'
```

By default, this writes the retained protein-link tables to standard output.
Use `--output links.txt` to save that summary instead.

Write data for the existing JavaScript renderer:

```bash
cargo run -p clinker-cli -- input-a.gbk input-b.gbk --plot plot-data.json
```

The generated file contains `clusters`, `links`, and an empty `groups` array.
Gene, locus, and cluster IDs are stable within a run; translations are kept in
memory only while comparing proteins and are not written to the plot data.

Build an optimized distributable binary:

```bash
cargo build --release -p clinker-cli
```

The resulting executable is `target/release/clinker-rs`. End users download a
release binary; they do not need Cargo or Rust installed.

## Dependency management

Dependencies are declared by crate name and version in a package's
`Cargo.toml`, for example:

```toml
[dependencies]
gb-io = "0.9"
```

Cargo downloads the crate and its transitive dependencies from crates.io,
selects compatible versions, and records the exact resolved versions in
`Cargo.lock`. `clinker-core` uses `gb-io` for GenBank parsing and `bio` for
global protein alignment.

## Browser prototype

`web/` contains the static upload UI and a Web Worker. Build instructions are
in [web/README.md](web/README.md). The currently installed Homebrew Rust lacks
the `wasm32-unknown-unknown` target manager, so the WebAssembly build cannot be
verified on this machine until Rust is installed through `rustup`.
