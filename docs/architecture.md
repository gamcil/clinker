# Architecture and development

The repository root contains the clinker Rust implementation. It is a
[Cargo workspace](https://doc.rust-lang.org/book/ch14-03-cargo-workspaces.html):
one repository containing several related Rust packages which share one lock
file, build directory, and dependency resolution.

## Packages

- `clinker-core` holds platform-independent GenBank, GFF3/FASTA parsing, accelerated global alignment,
  grouping, ordering, and plot-data code. It takes input bytes rather than paths
  so both frontends execute the same analysis implementation.
- `clinker-cli` is the small native command-line frontend. Its release binary
  is named `clinker-rs`.
- `clinker-wasm` is a thin `wasm-bindgen` adapter used by the static web app.

`Cargo.toml` is Rust's package manifest. It declares a package's name,
version, Rust edition, and dependencies. `Cargo.lock` is generated by Cargo
after resolving compatible dependency versions; commit it for applications so
local builds and release builds use the same dependency graph.

## Commands

Run all commands below from the repository root. To run all tests:

```bash
cargo test --workspace
```

Run the CLI against an existing fixture:

```bash
cargo run -p clinker-cli -- examples/'A. versicolor CBS 583.65.gbk'
```

GFF3 inputs may contain an embedded `##FASTA` section or use a companion FASTA
with the same stem (`.fa`, `.fsa`, `.fna`, `.fasta`, or `.faa`). Directories are
searched recursively for supported annotation files:

```bash
cargo run -p clinker-cli -- annotations/cluster.gff3
cargo run -p clinker-cli -- annotations/
```

By default, this writes the retained protein-link tables to standard output.
Use `--output links.txt` to save that summary instead.

Native protein comparisons run in parallel. `--jobs 0`
(the default) uses the available CPU threads; pass `--jobs 1` for serial
alignment or another positive value to set the size of the local thread pool.

Enable the optional k-mer prefilter to reduce protein comparisons (off by default):

```bash
cargo run -p clinker-cli -- annotations/ --prefilter
cargo run -p clinker-cli -- annotations/ --prefilter --kmer-size 5 --min-shared-kmers 8
```

The default filter requires three distinct shared 3-mers. More stringent settings
can be faster but may miss distant homologues. Both modes use the same alignment
batch planner and alignment loop. Work is split into at most 1,600 pairs per
batch, distributed by Rayon on native builds and Web Workers in the browser.
Native and browser inputs use the same core preparation, batch API and workload
counts. Unfiltered pairs are expanded on demand within each batch; filtered
candidate pairs are currently collected before alignment.

Alignment buffers are reused across batches. When extending a session, these
options apply to new comparisons; existing links are retained.

Write data for the JavaScript renderer or a portable offline HTML figure:

```bash
cargo run -p clinker-cli -- input-a.gbk input-b.gbk --plot plot-data.json
cargo run -p clinker-cli -- input-a.gbk input-b.gbk --plot figure.html
```

Select record intervals with 1-based inclusive coordinates, or split every
record in a multi-record GenBank file into an independent cluster:

```bash
cargo run -p clinker-cli -- input.gbk --ranges scaffold_1:15000-40000
cargo run -p clinker-cli -- input.gbk --as-separate-clusters
```

Circular records are rotated automatically when a gene crosses the origin.
Pass `--dont-set-origin` to retain the original coordinates.

Build annotation-only plots, or seed homology groups and colours from
two-column CSV files:

```bash
cargo run -p clinker-cli -- input.gbk --no-align --plot annotations.html
cargo run -p clinker-cli -- input-a.gbk input-b.gbk \
  --gene-functions functions.csv --colour-map colours.csv --plot figure.html
```

`functions.csv` contains `gene,function` rows. `colours.csv` contains
`function,colour` rows. Function groups are extended by retained homology links
when alignment is enabled.

Save full analysis state, reopen it later, or append more GenBank inputs without
recomputing links between clusters already in the session:

```bash
cargo run -p clinker-cli -- input-a.gbk input-b.gbk --session analysis.json
cargo run -p clinker-cli -- --session analysis.json --plot figure.html
cargo run -p clinker-cli -- input-c.gbk --session analysis.json
```

Analysis sessions retain protein translations and are therefore larger than
plot-data JSON. They use a versioned `clinker-analysis` schema shared by the
CLI and web application. When the web app exports a versioned
`clinker-project`, it embeds this analysis state alongside the plot data,
renderer appearance, and editing state. The web app therefore needs only one
project file to preserve everything available for a run. The web Open action
accepts this complete project format only. The CLI writes the same format
with `--project comparison.json`; `--session` remains the native analysis
continuation format. See [project formats](project-format.md).

Plot data contains `clusters`, `links`, and connected-component `groups`.
Gene, locus, and cluster IDs are stable within a run; translations are retained
only during analysis and are not written to browser data. Existing output files
are protected unless `--force` is supplied.

Build an optimized distributable binary:

```bash
cargo build --release -p clinker-cli
```

The resulting executable is `target/release/clinker-rs`. End users download a
release binary; they do not need Cargo or Rust installed.

## Dependency management

Dependencies are declared by crate name and version in a package's
`Cargo.toml`, for example:

```toml
[dependencies]
gb-io = "0.9"
```

Cargo downloads the crate and its transitive dependencies from crates.io,
selects compatible versions, and records the exact resolved versions in
`Cargo.lock`. `clinker-core` uses `gb-io` for GenBank, Rust Bio for GFF3/FASTA,
and `block-aligner` for SIMD-accelerated global protein alignment.

## Browser application

`web/src/` contains the static upload UI and its Web Workers.
`web/dist/` is the generated static application, including vendor modules and WASM. Build instructions
are in [web/README.md](../web/README.md). The application runs parsing, alignment,
grouping, ordering, and layout locally through `clinker-core` compiled to WASM.

`web/src/viewer/` holds the shared figure lifecycle and project/tree data helpers.
The browser entry supplies analysis results and application controls; the viewer
does not start workers or import the analysis entry. The native local viewer
will use this same component with native results.

## Features and releases

[features.md](features.md) records implemented user workflows and the features
still needed before the Rust application can replace the Python package. CI
tests native builds on Linux, macOS, and Windows and assembles the WASM web
application. The combined validation and Pages workflow runs on pushes and pull
requests; successful runs on `rust-port` also deploy the tested web build to
GitHub Pages. Tags of the form `rust-vX.Y.Z` run the same checks and publish
native CLI archives and the tested static web archive only after every check
passes. The tag version must match the Cargo workspace version.

Release instructions and remaining manual checks are in [releasing.md](releasing.md).
